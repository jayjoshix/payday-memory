## Tatum

The [pricing FAQ](https://tatum.io/pricing) says free plans can remain free, lists100K lifetime credits,2 keys and3 requests/second, and warns of automatic tier upgrades unless disabled in account settings. This says nothing about this account's remaining allowance. The application refuses live reads without a recent local account checklist confirming the free plan, disabled upgrades, no paid billing arrangement and sufficient remaining credits. Do not enter invented quota values.

[RPC connection documentation](https://docs.tatum.io/reference/how-to-connect-rpc-gateway), rechecked on 8 November, prices standard RPC methods at 2 credits and excludes higher-cost Debug/Trace/archive work. The planned latest-state balance, transaction and public-package reads use that standard-read bound. This does not verify the account's remaining credit count or method access. Three application RPC reads is a request cap, not a claim of three credits.

[Sui migration notice](https://docs.tatum.io/changelog/sui-json-rpc-migration-notice) states JSON-RPC endpoints are decommissioned after July2026. Some reference pages still list legacy methods; this implementation uses none. [Current gRPC announcement](https://docs.tatum.io/changelog/sui-grpc-available-tatum) and [Tatum Sui method inventory](https://docs.tatum.io/reference/rpc-sui) list `sui.rpc.v2.StateService/GetBalance` and `sui.rpc.v2.LedgerService/GetTransaction` at `sui-mainnet-grpc.gateway.tatum.io:443`. [Migration guide](https://docs.tatum.io/oa/reference/sui-grpc) specifies `x-api-key` metadata. The native TLS HTTP/2 transport uses the official Mysten-generated service clients. This account passed genuine GetBalance and GetObject calls. GetTransaction validation is implemented and tested offline, but no live transaction digest was supplied or receipt claimed.

`TatumAdapter` exposes only a balance and a specific transaction read. It has no signer or transaction submission method. One invocation makes at most3 sequential RPC calls, caches repeated balances and stops on quota errors. There is deliberately no wallet-history crawl: one supplied digest does not represent complete history. A receipt uses successful effects, the native token type, matching recipient, positive exact amount and an index-qualified balance-change identity. Balance changes are net wallet changes, not proof of an invoice's business purpose. Public addresses need no ownership claim. Supply a public address and optional public digest yourself; the app does not harvest identities.

The captured balance can replace the fictional scenario's opening snapshot in the clearly labelled connected preview. It never inherits fictional historical receipts. Receipt allocation and client aliases remain user assertions. A failed call keeps local replay available and must show the old snapshot as stale.

## Walrus Memory

[Quickstart](https://docs.wal.app/walrus-memory/getting-started/quick-start) directs application builders to the hosted Memory Playground to generate an account and delegate, then use `@mysten-incubation/memwal`. The account object ID, delegate public key and delegate private credential are three different values. `MEMWAL_AGENT_ID` is the delegate's public key on the event form. Never paste the private key into chat. Obtain it through the [official hosted dashboard](https://memory.walrus.xyz/) and store it only in `.env.local`.

[Managed relayer documentation](https://docs.wal.app/walrus-memory/relayer/public-relayer), rechecked on 8 November, states the Mainnet service pays WAL storage and SUI gas for relayed writes subject to shared limits, with no SLA. The builder confirmed that account/delegate onboarding required no payment. The corrected account authenticates on Mainnet, but its metadata does not expose numeric remaining write capacity or storage duration. A one-record sponsored probe inspects actual expiry, while complete retrieval checks all source and manifest expiries separately from monetary safety. If any step asks for tokens, a card, a deposit, a self-funded transaction or paid renewal, stop. No raw Walrus upload fallback is implemented.

Only the fixed managed Mainnet endpoint `https://relayer.memory.walrus.xyz` is used. The relayer handles fictional records in plaintext before encryption, as disclosed in its docs. The app uses `remember` and never `analyze` (which invokes provider LLM extraction). Deterministic local code computes every lesson. Provider-managed embedding is part of the sponsor service; no separately billed model service is configured.

The installed SDK discovers Sui RPC URLs from the relayer's `/config` when building its ephemeral Seal session. A genuine 8 November configuration read confirmed Mainnet and an advertised gRPC transport. The application intercepts only the SDK's public immutable package-object check in process and routes it through Tatum native `LedgerService/GetObject`. The one-object batch form is supported; JSON-RPC fallback, arbitrary objects, writes, private headers and redirects are rejected. Five offline tests exercise the installed SDK paths. No advertised third-party RPC provider is contacted. This bridge passed genuine package reads during completed managed Mainnet content operations; actual returned metadata is recorded in the proof manifest.

The [SDK API reference](https://docs.wal.app/walrus-memory/sdk/api-reference) and installed0.1.13 declarations confirm accepted jobs are not completed memories, `getRememberStatus` reports completion, and `remember` accepts a namespace-scoped idempotency key plus content dedupe. The app persists the stable key and provider job ID, polls at most30seconds per selected job with bounded backoff, resumes the same pending job after restart and never retries quota failures automatically. Only returned blob IDs with completed status count. Three submission attempts per record are the application maximum; normal tests never call the SDK network.

### Complete recovery

The default curated publication contains20 meaningful records: one complete corrected dataset, all14 source observations, one reimbursement correction, three current lessons and the prior Paper Lane lesson frozen on4 November, followed by one separately confirmed manifest. On5 November the correction removes the reimbursement from eligible income history; Paper Lane changes from three eligible payments to two and displays insufficient history. Original receipts and allocations remain available, and actual held cash is unchanged. The new lesson links to the prior lesson; recovery recomputes each lesson at its own knowledge date and selects the current effective version. All are authored fictional records, not evidence that historical Mainnet writes occurred.

The publication dataset has a dedicated `payday-memory-fictional-v1-corrected-v1` identity. An operator can alternatively pass `--dataset=path/to/payday-memory-local-sample.json` to publish the UI's exported fictional sample, including its corrections. Exports are schema-validated, require fictional provenance and a fictional wallet, and receive a deterministic content-specific dataset ID. Each content identity has its own durable outbox, preventing changed exports from mutating an already published ID. Connected chain samples and real user records are refused by this publication command. The application caps curated sources at24 plus one manifest.

The manifest contains every record ID, content hash and returned blob ID. `listMemories` enumerates inventory across at most3 pages, following `has_more` even when a namespace-filtered page is empty. `recall` retrieves content for explanation and recovery, but it is never trusted as an exhaustive ledger. Recovery accepts content only when every expected blob exists and every schema/hash/ID matches. Missing semantic hits cause an explicit incomplete restore; local data is retained. The domain recomputes lessons and compares them with retrieved lessons. `memory:verify` first retrieves the sponsor-stored manifest, then writes to a newly created empty disposable directory, never reads the original dataset database and does not delete any provider memory.

After publishing, inspect returned `expires_at`/`end_epoch` inventory metadata and verify availability through judging. The full-set recovery records actual expiry independently from billing safety; null remains unknown. No permanent storage claim or renewal is made.

## Operator sequence

1. Copy `.env.example` to `.env.local` and fill only named application values privately. Do not share keys in screenshots or commits.
2. Inspect both official dashboards. Copy `evidence/account-checks.example.json` to `data/account-checks.json`, replace the timestamp and actual quota/fee facts, then set booleans only when verified. The file expires after 24 hours. Unknown numerical Memory capacity stays zero with an explicitly verified provider-enforced free-limit policy; this does not mean zero remaining records. Retention remains unverified until actually observed. Tatum's upgrades and remaining credits must be checked before any Tatum request.
3. `npm run sponsors:check` only prints readiness and writes redacted evidence; it consumes no credits.
4. `npm run memory:account-check -- --live` makes a bounded signed metadata inspection with no content retrieval or writes. This passed for the corrected account on 8 November.
5. After Tatum checks pass, `npm run memory:probe -- --live` publishes at most one meaningful fictional observation, waits for completion, retrieves that exact content and inspects returned expiry. Its package-validation read uses only Tatum. No numeric remaining allowance or future retention is invented.
6. `npm run sponsors:check -- --live` performs up to two product Tatum reads, plus at most one SDK package-validation read, and one Memory write/completion/retrieval attempt. Retention is assessed separately from the verified free route. The smoke proof is one fictional observation, not ten memories.
7. `npm run memory:publish -- --live --max-records=1` advances the corrected fictional publication's bounded durable outbox. To select an exported fictional correction instead, add `--dataset=path/to/payday-memory-local-sample.json` on every invocation for that publication. Increase the work cap only within verified free access; maximum 25. Once every source record is complete, run again to publish the single manifest (a separate capped invocation). No paid top-up is offered.
8. `npm run memory:verify -- --live` retrieves the confirmed manifest and all records into a fresh recovery directory and updates redacted proof. Missing/pending/failed writes never pass recovery.

Run one operator command at a time. The local outbox lives under ignored `data/`; captured public evidence contains provider IDs/times/hashes, never keys. Review captured public data before publication. Sponsor readiness remains pending until real operations return their evidence. All normal tests, seed/reset and browser demos stay offline.
